# Whole-experience audit

Goal: understand Anantam, explore its one contribution, watch what the environment tests, understand outcomes, and inspect relevant evidence. The user explicitly rejected a sparse company introduction followed by one concealed accordion; passing functional tests did not satisfy that brief.

| Confirmed friction | Implemented change | Evidence checked |
| --- | --- | --- |
| Product proof arrives too late and is mostly concealed. | Compact centered identity, substantial visible evacuation stage, published outcomes and connected explanation in normal reading order. | Desktop/phone full-page captures and contribution-position checks. |
| Motion decorates a static diagram without enabling exploration. | Six complete authenticated reference replays across three worlds; play, pause, restart, scrub and rule choices. | Upstream replay verification; source hashes; exact recorded endpoint, pause and restart browser checks. |
| Outcome bars alone offer little human meaning. | Two exact 241-person pictographs with visible counts, hover grouping and an explicit touch/keyboard action. | Source-count assertions; intermediate transform measurement; touch, keyboard and reduced-motion checks. |
| More evacuated people appear beside a lower score. | Explicit explanation of summed counts versus execution quality and family balance, with a scoring link. | Current home copy and desktop/phone captures. |
| Scenario destination is mostly selectors and tables. | All ten real initial layouts, supported replay examples, nearby published evidence and native phone selection above the map. | Scenario captures, geometry checks and original analytical regressions. |
| Playback controls fall below the artifact on phones. | Controls sit directly below the map before its longer explanation. | Bounding-box adjacency check and phone capture. |
| Selecting a static world can leave a previous replay download visible. | Every load hides the record link and removes its URL; only current successful loads reveal it. | Supported → static-world transition regression. |
| Scenario action reloads the same route and loses model context. | In-place Results reveal; selected world/model remain in the URL and profile backlinks. | Round-trip navigation and per-scenario-link checks. |
| Methodology’s pipeline is a generic six-item grid. | Connected observation–decision–simulation loop, then verification and scoring; stages reveal their explanation. | Keyboard selection, stage-copy checks and method captures. |
| Identical large white containers dominate all tasks. | Presenting, inspecting, comparing and reading use different compositions; evidence pages shed enclosing panels. | Current home/world/model/compare/method capture matrix. |

Fresh independent review confirmed the substantial whole-site direction, then identified three bounded interface issues and documentation accuracy. The interface fixes and documentation were scored resolved in a later verdict. Runtime motion and interaction verification belongs to the browser checks and actual visitor walkthrough, not that source/capture-only review.

Automated accessibility scans cover selected WCAG A/AA rules. Keyboard, reduced motion and touch-equivalent behavior were checked separately. Physical-device and manual screen-reader testing were not performed; this is not a recruited-participant usability study.
